## 工作原理

`.github/workflows/release.yml` 定义了名为 **Release** 的工作流，触发方式：

1. **推送 `v*` 标签**（如 `v1.4.0`）—— 常规发版走这条
2. **GitHub Release 发布**（`types: [published]`）
3. **手动触发**（`workflow_dispatch`）—— 用于重跑失败的构建

触发后 GitHub Actions 在 `windows-latest` 虚拟机上执行：

```
checkout 代码
  → 安装 Node 22
  → 安装 Rust stable
  → 缓存 Rust 编译产物 (Swatinem/rust-cache)
  → npm ci 安装前端依赖
  → npm run tauri build 编译 Release
  → softprops/action-gh-release 上传 NSIS 安装包到 Release
```

整个流程约 **10–20 分钟**（首次构建需全量编译 Rust，之后走缓存会快很多）。

## 发布前置条件

- [x] 代码已提交
- [x] 远程仓库已存在
- [x] 发布工作流已存在（本仓库已就绪）
- [ ] 下一次要发布的版本号（见下文"升版本号"）
- [ ] 有 GitHub 账号且能推送（HTTPS 推送需配置 token / GitHub CLI）

## 完整发布步骤

### 第 1 步：提交本地改动

```bash
git add .
git commit -m "你的提交说明"
```

### 第 2 步：推送代码到 GitHub

```bash
git push origin master
```

### 第 3 步：升版本号

> 每次发布前必须升版本，因为已经打过的 tag 不能重复使用。

把以下 3 个文件的版本号 `1.3.0` 改成新版本（如 `1.4.0`）：

1. `package.json`
2. `src-tauri/tauri.conf.json`
3. `src-tauri/Cargo.toml`

然后同步 lock 文件并提交推送：

```bash
npm install --package-lock-only     # 同步 package-lock.json 里的版本号
git add .
git commit -m "chore: bump version to 1.4.0"
git push origin master
```

### 第 4 步：打标签并推送（触发自动发布）

```bash
git tag v1.4.0
git push origin v1.4.0
```

推送标签的瞬间即触发 `Release` 工作流。

### 第 5 步：确认构建通过

进入 GitHub 仓库 → **Actions** 标签页，查看名为 **Release** 的运行记录，等待绿色 ✓。

## 查看构建结果

构建成功后：

1. 进入 GitHub 仓库 → **Releases** 页面
2. 找到对应版本的 Release（工作流会自动生成）
3. 下载 `Proxy.Switch_x.x.x_x64-setup.exe`

也可以直接在 Actions 运行详情页的 "Upload to Release" 步骤里找到上传的产物。

## 手动重跑构建

工作流支持手动触发（`workflow_dispatch`）：

1. GitHub 仓库 → **Actions** 标签页
2. 左侧选择 **Release**
3. 右侧 **Run workflow** 下拉 → 选择分支 → **Run workflow**

> 用于构建失败后的重跑，无需新打标签。但 `softprops/action-gh-release` 依赖 tag 上下文，常规发版仍以"推标签"为主。

## 常见问题

### Q1：首次构建很慢，正常吗？

正常。GitHub 的 Windows 机器需要从零编译所有 Rust 依赖。`Swatinem/rust-cache` 会在后续运行时缓存 `src-tauri/target`，第二次起显著加快。

### Q2：安装包下载后提示"未知发布者 / SmartScreen 警告"？

因为安装包未做代码签名。这是预期行为，点击 **更多信息 → 仍要运行** 即可。要彻底消除需要购买代码签名证书（每年付费），暂不在范围内。

### Q3：`npm ci` 报错 / lock 文件不同步？

确认执行过 `npm install --package-lock-only`，且 `package-lock.json` 已提交到仓库。`npm ci` 严格要求 lock 文件与 `package.json` 一致。

### Q4：仓库是私有的，能不能发布？

可以。私有仓库的 Release 同样能生成安装包，只是下载需要登录 GitHub；且私有仓库的 Actions 免费额度有限（每月 2000 分钟左右），一次 Tauri 构建约消耗 15–20 分钟。

### Q5：为什么只有 Windows 安装包？

`release.yml` 只配置了 `windows-latest` 与 NSIS 打包目标（见 `tauri.conf.json` 的 `bundle.targets: "nsis"`）。本项目当前只面向 Windows 桌面端，如需 macOS/Linux 需要额外扩展工作流。

### Q6：推送遇到认证问题？

HTTPS 方式推送 GitHub 需要：

```bash
gh auth login          # 使用 GitHub CLI（推荐）
# 或者
# 使用 Personal Access Token 作为密码
git push origin master
```
